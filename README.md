# نظام إدارة الموظفين والحضور والانصراف (MVP)

تطبيق ويب متكامل، متجاوب (Desktop/Mobile)، ومصمم باللغة العربية (RTL) لإدارة الحضور والانصراف الداخلي للمنشآت.

---

## 🛠️ البيئة والتقنيات المستخدمة

- **الإطار الخادمي**: Laravel 13 (مع PHP 8.5)
- **قاعدة البيانات**: MariaDB / MySQL
- **المصادقة**: Laravel Breeze (Blade Stack)
- **التصميم والواجهات**: Tailwind CSS + Alpine.js (تصميم عربي RTL بالكامل مع خط Noto Sans Arabic)
- **توقيت النظام**: UTC للتخزين في قاعدة البيانات، و`Asia/Riyadh` للعرض والمدخلات المحلية.

---

## 🚀 التثبيت والتشغيل المحلي

### 1. المتطلبات المبسطة
- PHP >= 8.2 مع امتدادات `pdo_mysql`, `mbstring`, `openssl`
- MariaDB / MySQL
- Composer & Node.js / npm

### 2. إعداد قاعدة البيانات والبيئة
1. قم بإنشاء قاعدة بيانات باسم `employee_manager`:
```sql
CREATE DATABASE employee_manager CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'employee_mgr'@'localhost' IDENTIFIED BY 'secret123';
GRANT ALL PRIVILEGES ON employee_manager.* TO 'employee_mgr'@'localhost';
FLUSH PRIVILEGES;
```

2. انسخ ملف `.env.example` إلى `.env`:
```bash
cp .env.example .env
```

3. اضبط إعدادات الاتصال بقاعدة البيانات في `.env`:
```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=employee_manager
DB_USERNAME=employee_mgr
DB_PASSWORD=secret123

APP_TIMEZONE=Asia/Riyadh
APP_LOCALE=ar
```

4. نفذ التهجير والبيانات التجريبية (Migrations & Seeders):
```bash
php artisan migrate:fresh --seed
```

5. بناء أصول الواجهة وتطبيق البناء:
```bash
npm install
npm run build
```

6. تشغيل السيرفر المحلي:
```bash
php artisan serve
```
افتح المتصفح على `http://localhost:8000`.

## 🧪 تشغيل الاختبارات الآلية (Automated Tests)

يحتوي المشروع على **17 اختباراً وظيفياً شتملاً** يغطي جميع متطلبات الأمان وقواعد العمل:

```bash
php artisan test
```

### التغطية الفعالة للاختبارات:
1. منع الموظف العادي من الوصول أو الاطلاع على سجلات موظفين آخرين.
2. منع الحضور المكرر لنفس التاريخ المحلي.
3. منع تسجيل الانصراف بدون تسجيل حضور مفتوح.
4. منع تسجيل حضور جديد أثناء وجود جلسة مفتوحة.
5. احتساب ومزامنة الجلسات التي تعبر منتصف الليل وإسنادها لتاريخ البداية.
6. التحقق من صلاحيات المدير ومنع التعديلات الزمنية غير المنطقية.
7. تسجيل التعديلات اليدوية للمدير في `attendance_audit_logs` مع القيم السابقة والجديدة والسبب والوقت.
8. منع الحسابات المعطلة (`is_active = false`) من الدخول أو مواصلة الجلسات النشطة.
9. مطابقة الفلاتر والتصنيفات بين العرض والتصدير كملف CSV مع الحماية من CSV Formula Injection.

## 📱 سيناريوهات التجربة للعميل

### 1. سيناريو الموظف (Employee Flow):
1. سجل الدخول ببريد `sara@example.com` وكلمة المرور `password`.
2. تظهر لوحة التحكم الخاصة بالموظف حالة عدم وجود حضور اليوم.
3. اضغط على زر **«تسجيل الحضور»**؛ ستتحدث الحالة إلى **«جلسة حضور نشطة حالياً»** ويظهر وقت الحضور.
4. اضغط على زر **«تسجيل الانصراف»**؛ ستكتمل الجلسة وتُحسب المدة بالدقائق والساعات تلقائياً.
5. حاول النقر مجدداً أو فتح جلسة أخرى؛ يمنعك النظام طبقاً لقواعد العمل.

### 2. سيناريو مدير النظام (Admin Flow):
1. سجل الدخول ببريد `admin@example.com` وكلمة المرور `password`.
2. استعرض لوحة المؤشرات (عدد الموظفين الفعالين، حضور اليوم، الجلسات المفتوحة، والسجلات غير المكتملة).
3. يظهر تنبيه وجود **«سجل غير مكتمل»** للموظف `khaled@example.com`.
4. انقر على **«إدخال وقت الانصراف»**، أدخل الوقت والتاريخ المحلي وسبب التعديل المباشر (مثل: "نسي الموظف تسجيل الانصراف").
5. انتقل لصفحة **«سجل التعديلات»** لتشاهد توثيق التدقيق الأمني (Audit Log) الكامل للتعديل.
6. انتقل لصفحة **«التقارير»** واستخدم الفلاتر، ثم جرب زر **«طباعة التقرير»** (تنسيق نظيف يخفي القوائم والأزرار تلقائياً)، أو زر **«تصدير ملف CSV»**.
7. انتقل لصفحة **«الموظفين»** وقم بإنشاء موظف جديد بكلمة مرور مؤقتة، أو قم بتعطيل حساب موظف وافحص منعه المباشر من الدخول.

## ⚠️ القيود والأعمال المستقبلية (قبل الإنتاج)

1. **الإنتاج الحقيقي**: يلزم إيقاف `APP_DEBUG=false` وتثبيت شهادة SSL.
2. **قواعد البيانات**: التأكد من تشغيل التغليف والمعاملات المالية للحماية القصوى.
3. **تطبيق الجوال وGPS**: غير مشمولة في هذه النسخة التجريبية (MVP) كما هو محدد في المتطلبات.
